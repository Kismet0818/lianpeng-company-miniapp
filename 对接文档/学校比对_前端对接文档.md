# 学校比对前端对接文档

> 后端完成日期：2026-09-14  
> 本地基础地址：`http://localhost:8080`（本次实测使用 `http://127.0.0.1:18081`）  
> 鉴权：无需登录；接口已加入公开路径和公开查询限流。

## 1. 学校搜索

```http
GET /api/school-compare/search?level=junior&keyword=实验&page=1&size=20
```

参数：`level` 必填，仅 `junior`/`high`；`keyword` 必填，trim 后 1～50 字符；`page` 默认 1、范围 1～200；`size` 默认 20、范围 1～50。

`junior` 搜索 `junior_high_school`；`high` 合并搜索 `score_query_tool_school`（市重点、区重点等分数查询高中）与 `general_high_school`（一般高中）。全称和简称均参与参数化包含查询。结果按完全匹配、前缀匹配、包含匹配，再按名称、来源、ID 稳定排序，最后统一分页。

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "records": [{
      "id": 1,
      "compareKey": "domestic:junior:1",
      "schoolSource": "junior",
      "kind": "junior",
      "name": "华东师范大学宝山实验学校",
      "shortName": "华师宝实",
      "district": "宝山区",
      "level": "初中",
      "schoolType": "公办初中",
      "nature": "公办",
      "tuitionMin": null,
      "tuitionMax": null,
      "boardingInfo": null,
      "logoUrl": null,
      "address": null,
      "description": null,
      "officialWebsite": null,
      "schedule": null,
      "teachingFeatures": null,
      "campusArea": null
    }],
    "page": 1,

```

合法的空搜索返回 HTTP 200、`code=200`、`records=[]`、`total=0`。缺参、非法学段、超长关键词或非法分页返回 HTTP 400、`code=400`。

## 2. 批量获取对比详情

```http
POST /api/school-compare/details
Content-Type: application/json
```

推荐请求字段使用 `schoolSource`；为兼容搜索列表的轻量引用，后端也接受别名 `source`。

```json
{
  "schools": [
    { "schoolSource": "junior", "id": 2 },
    { "schoolSource": "junior", "id": 1 },
    { "schoolSource": "junior", "id": 2 }
  ]
}
```

成功响应会按首次出现顺序返回 2、1，并删除第二个 `junior/2`：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "schoolSystem": "domestic",
    "level": "junior",
    "schools": [
      { "id": 2, "compareKey": "domestic:junior:2", "schoolSource": "junior", "kind": "junior", "name": "华东师范大学附属宝山宝杨实验学校", "level": "初中", "nature": "公办" },
      { "id": 1, "compareKey": "domestic:junior:1", "schoolSource": "junior", "kind": "junior", "name": "华东师范大学宝山实验学校", "level": "初中", "nature": "公办" }
    ]
  }
}
```

规则：去重后 1～6 所；初中只能选 `junior`，高中可混选 `score` 与 `general`；初高中混选返回 HTTP 400；任一精确来源/ID 不存在返回 HTTP 404，例如 `学校不存在: junior/999999`。详情按来源分组批量查询，不逐校访问数据库。

## 3. compareKey 与前端流程

| 来源 | compareKey |
|---|---|
| 初中 `junior` | `domestic:junior:{id}` |
| 分数查询高中 `score` | `domestic:score:{id}` |
| 一般高中 `general` | `domestic:general:{id}` |

前端应把 `compareKey` 作为加入、移除、去重和本地持久化的唯一键，不能只使用数字 `id` 或名称。提交详情时保存并回传 `schoolSource + id`。

调用流程：选择学段 → 输入关键词调用 search → 用 `compareKey` 加入/移除本地列表 → 本地先提示最多 6 所和不可跨学段 → 点击开始对比后一次 POST details → 以响应中的 `schools` 顺序渲染列。

切换学段时建议清空当前列表或明确二次确认。搜索空结果提示“未找到相关学校”；400 直接展示 `msg`；404 提示学校资料已变化并让用户重新选择；网络/5xx 提示稍后重试。

## 4. 对比字段映射

| 页面语义 | 返回字段 | 说明 |
|---|---|---|
| 学校名称 | `name` | 必有 |
| 区域 | `district` | 缺失为 `null` |
| 学段 | `level` | `初中`/`高中` |
| 办学性质 | 优先 `nature`，详情可展示 `schoolType` | `nature` 从现有类型归一为公办/民办 |
| 学费 | `tuitionMin`、`tuitionMax` | 万元/年；缺失不猜测 |
| 寄宿 | `boardingInfo` | 缺失为 `null` |
| 校徽/背景图 | `logoUrl` | 缺失为 `null` |
| 地址 | `address` | 可选扩展行 |
| 学校介绍 | `description` | 可选扩展行 |
| 官网 | `officialWebsite` | 可选扩展行 |
| 作息 | `schedule` | 可选扩展行 |
| 教学特色 | `teachingFeatures` | 可选扩展行 |
| 占地面积 | `campusArea` | 平方米；缺失为 `null` |

## 5. 可重复测试与实际结果

```bash
curl "http://localhost:8080/api/school-compare/search?level=junior&keyword=实验&page=1&size=20"
curl "http://localhost:8080/api/school-compare/search?level=high&keyword=中学&page=1&size=50"
curl -X POST "http://localhost:8080/api/school-compare/details" -H "Content-Type: application/json" -d "{\"schools\":[{\"schoolSource\":\"junior\",\"id\":1},{\"schoolSource\":\"junior\",\"id\":2}]}"
```

2026-09-14 本地库实测：初中关键词命中 138 条；高中“中学”命中 260 条且同时包含 `score`、`general`；无结果和单引号关键词均为 200 空数组；51 字关键词和非法学段为 400。详情 1 所、6 所成功，7 所为 400；重复项按首次顺序去重；初高中混选为 400；不存在的精确来源/ID 为 404；大量缺失详情字段稳定返回 `null`，无 500。

本地两张高中表当前没有重叠的数字主键；使用 `score/1 + general/1` 时，后端能找到前者并明确返回 `general/1` 不存在，证明查询与去重均包含来源，不会静默串到 `score/1`。

## 6. 与原需求的差异及限制

- 新增独立 `/api/school-compare/**`，未改变体制外旧接口 `POST /api/schools/compare` 的请求或语义。
- 请求主字段保持原文档的 `schoolSource`，额外兼容 `source` 别名。
- 当前数据没有名称拼音字段，因此只对全称和简称做完全/前缀/包含优先级排序。
- 搜索先合并命中数据再统一排序分页，适合当前数据规模；若未来达到大规模数据量，应下推为数据库统一检索视图或全文索引。
- 本次未修改数据库，也未部署云环境。
