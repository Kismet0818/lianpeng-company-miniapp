# 最近浏览多学校来源前端交接（2026-09-11）

## 故障原因

旧版首页只把数字 `id` 写入 `recentSchoolIds`，请求 `POST /api/schools/batch` 时也只传 `{ ids: [...] }`。小学、初中、高中、体制外学校分别使用不同数据表，数字 ID 会重复；因此 `id` 单独不能代表一所学校。旧接口默认按体制外学校表查询，小学便会出现“学校不存在”。

## 后端修复

新增登录接口：

```http
GET /api/user/activity/recent?limit=20
Authorization: Bearer <token>
```

接口直接根据服务端浏览记录查询，始终使用 `schoolSource + schoolId` 复合身份，返回时间倒序且同一学校去重。支持来源：`international`、`primary`、`junior`、`general`、`score`。

响应中每项至少包含：

```json
{
  "id": 1,
  "schoolId": 1,
  "schoolSource": "primary",
  "name": "学校名称",
  "schoolName": "学校名称",
  "district": "浦东新区",
  "logoUrl": "https://...",
  "lastViewTime": "2026-09-11T12:00:00"
}
```

## 前端必须修改

1. 首页“最近浏览”登录态下改调 `GET /api/user/activity/recent?limit=20`，请求必须带 JWT。
2. 卡片点击详情时同时传 `schoolSource` 和 `schoolId`，按来源进入对应详情页。
3. 本地缓存键不得再只用数字 ID；如继续做离线缓存，使用 `${schoolSource}:${schoolId}`。
4. 老版本 `recentSchoolIds` 是有歧义的数据，升级后应清除；不得继续拿它请求 `/api/schools/batch`。
5. 未登录用户如需保留本机最近浏览，也必须把完整对象 `{ schoolSource, schoolId, ...摘要 }` 存入缓存。

## 验收用例

- 依次浏览数字 ID 相同的一所小学和一所体制外学校，最近浏览中应同时出现两所且跳转正确。
- 浏览小学后回首页，点击“最近浏览”不再出现“学校不存在”。
- 重复浏览同一所学校只显示一次，并移动到最前。
- 学校被删除或停用时，后端跳过该记录，不让整个列表报错。
