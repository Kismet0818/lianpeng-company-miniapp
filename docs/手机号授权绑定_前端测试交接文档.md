# 联朋升学小程序：手机号授权绑定前端测试交接

## 目标

本功能是**首次进入时的强制手机号授权门禁**，不是个人中心里的可选绑定。

用户完成微信登录后，前端立即查询当前用户资料：

- `phone` 有值：正常进入首页。
- `phone` 为空：只显示全屏手机号授权页，禁止进入首页及其他业务页面。
- 授权成功：后端绑定手机号，随后放行进入首页。
- 用户拒绝或授权失败：停留在授权页，可以重试，但不能继续使用业务功能。

微信手机号能力仍然要求用户主动点击带有 `open-type="getPhoneNumber"` 的按钮，不能在代码中直接调起系统授权框。

## 前置条件

1. 必须使用已认证、具备手机号快速验证能力的正式小程序主体和对应 AppID。
2. 建议使用真机测试。开发者工具的模拟数据不一定能成功向微信换取手机号。
3. 用户必须已经完成微信登录，并保存 `/api/auth/wx-login` 返回的 JWT。
4. 请求沿用项目现有 API 域名；该域名须已配置在微信公众平台的 `request` 合法域名中。
5. `getPhoneNumber` 返回的 `code` 只能使用一次且有效期短，不能缓存或重复提交。

## 接入位置与启动流程

授权页应位于小程序启动流程中，建议作为独立页面，例如：

```text
pages/phone-auth/phone-auth
```

启动顺序必须是：

```text
小程序启动 → wx.login → /api/auth/wx-login → 保存 JWT
→ /api/user/profile
→ phone 为空：reLaunch 到手机号授权页
→ phone 有值：reLaunch 到首页
```

不要把手机号授权入口仅放在“我的”页面，也不要先让未授权用户浏览首页。

所有需要登录的页面应增加兜底检查：若没有 JWT 或用户 `phone` 为空，立即跳回登录/手机号授权流程，避免用户通过分享链接或页面栈绕过门禁。

## 授权页按钮

WXML：

```xml
<button
  open-type="getPhoneNumber"
  bindgetphonenumber="onGetPhoneNumber"
  loading="{{phoneBinding}}"
  disabled="{{phoneBinding}}"
>
  授权并绑定手机号
</button>
```

页面 JS：

```js
Page({
  data: {
    phoneBinding: false,
    phone: ''
  },

  async onGetPhoneNumber(e) {
    if (this.data.phoneBinding) return

    const code = e.detail && e.detail.code
    if (!code) {
      wx.showToast({ title: '需要授权手机号后才能继续使用', icon: 'none' })
      return
    }

    const token = wx.getStorageSync('token')
    if (!token) {
      wx.showToast({ title: '登录已失效，请重新登录', icon: 'none' })
      return
    }

    this.setData({ phoneBinding: true })
    wx.request({
      url: `${API_BASE_URL}/api/user/phone`,
      method: 'POST',
      header: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${token}`
      },
      data: { code },
      success: ({ data }) => {
        if (data && data.code === 200) {
          const phone = data.data && data.data.phone
          this.setData({ phone: phone || '' })
          wx.showToast({ title: '授权成功', icon: 'success' })
          setTimeout(() => wx.reLaunch({ url: '/pages/index/index' }), 500)
          return
        }
        wx.showToast({ title: (data && data.msg) || '手机号绑定失败', icon: 'none' })
      },
      fail: () => {
        wx.showToast({ title: '网络异常，请稍后重试', icon: 'none' })
      },
      complete: () => this.setData({ phoneBinding: false })
    })
  }
})
```

如果项目已有统一 `request` 封装，请复用封装，只需确保请求体为 `{ code }`，并携带 `Authorization: Bearer <JWT>`。

## 后端接口

### 绑定手机号

- 方法：`POST`
- 路径：`/api/user/phone`
- 鉴权：必须携带当前用户 JWT
- 请求头：`Authorization: Bearer <token>`
- 请求体：

```json
{
  "code": "getPhoneNumber 回调返回的一次性 code"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "phone": "13800138000"
  }
}
```

常见失败：

- 未携带或携带无效 JWT：返回 `401`。
- 没有 `code`：提示手机号授权凭证不能为空。
- `code` 过期、重复使用或不属于当前小程序：提示手机号授权失败，请重新点击授权。
- 微信服务暂不可用：提示稍后重试。

### 查询绑定结果

绑定成功后可请求：

- 方法：`GET`
- 路径：`/api/user/profile`
- 鉴权：`Authorization: Bearer <token>`

响应 `data.phone` 应为刚刚绑定的手机号。

## 管理后台验收

1. 打开现有管理后台，进入“用户管理”。
2. 输入管理密钥并刷新用户列表。
3. 按用户昵称、手机号或用户 ID 搜索刚测试的账号。
4. 用户卡片标题处应从“未绑定手机”变为完整手机号。
5. 管理接口 `/api/admin/users` 的对应记录中，`phone` 为完整手机号，`phoneMasked` 为脱敏手机号。

前端小程序不得调用 `/api/admin/**`，也不得接触或保存 `X-Admin-Key`。

## 必测用例

1. 首次进入：登录后 `phone` 为空，必须进入手机号授权页，不能看到首页业务内容。
2. 首次授权：授权后提示成功，进入首页，个人资料接口和管理后台均显示手机号。
3. 用户拒绝：不调用后端，停留在授权页并提示必须授权后才能继续使用。
4. 绕过检查：从分享链接、历史页面栈或直接页面路径进入时，未绑定用户仍会被拦回授权页。
5. 重复点击：加载期间按钮不可重复提交。
6. 旧 `code` 重放：应失败；重新点击按钮获取新 `code` 后可成功。
7. JWT 失效：重新登录，登录后再次判断是否需要手机号授权。
8. 已绑定用户：再次进入小程序直接进入首页，不重复弹出授权页。

## 不要再使用旧接口

`POST /api/auth/decrypt-phone` 是旧版 `encryptedData + iv + sessionKey` 兼容接口。新前端统一使用 `/api/user/phone`，只提交 `getPhoneNumber` 回调中的一次性 `code`。
