## 2. 安全红线

1. 不要把数据库密码、微信 AppSecret、OSS AccessKey、JWT Secret、管理密钥、服务器密码或 SSL 私钥写入本文、普通聊天、邮件、网盘明文文件或发布压缩包。
2. 历史 `HANDOVER.md`、应用配置、启动脚本、截图和旧交付包可能含明文凭据，只能受控查看，禁止原样外发。
3. 由于部分秘密曾出现在源码、文档或截图中，完成账号接管后应统一轮换：数据库、微信、OSS、JWT、管理端、Git/服务器和域名平台凭据。
4. 实际秘密通过公司密码管理器或一次性加密通道移交；用途与验收见同目录的《敏感凭据移交清单模板》。
5. 云数据库写操作必须先备份、先本地验证、再由公司负责人明确批准。禁止因本地连接失败而自动切到云库。
6. 不要执行 `git reset --hard`、整目录覆盖或批量回退。当前工作区有大量未提交改动，粗暴清理会丢失尚未发布的功能。

## 3. 系统结构

```text
微信小程序
  ├─ 正式环境 → 微信云托管 Spring Boot → 云 MySQL
  └─ 联调环境 → 局域网 Spring Boot:8080 → 本地 MySQL lpsx

```

后端技术栈：Java、Spring Boot、MyBatis、MySQL、JWT、Maven、Docker。  
前端技术栈：微信原生小程序。  
后端本地端口：`8080`；管理页本地端口：`3000`。

## 5. 环境边界与标准工作流

### 5.1 本地开发

1. 本地 MySQL 数据库名为 `lpsx`。
2. 先启动 MySQL，再启动 Spring Boot；Navicat 只是查看工具，不负责运行数据库或后端。
3. 前端联调时将开发配置指向后端电脑当前局域网 IP 的 `8080`，后端监听局域网；正式发布前切回云托管 HTTPS 地址。
4. 低内存电脑只运行后端和必要数据库工具；另一台电脑运行微信开发者工具，通过 Git 或目录同步工具取前端副本。不要长期直接打开网络共享目录作为微信项目。

### 5.2 数据库发布顺序

```text
本地建表/改表/导入
→ 本地查询与接口验收
→ 云库目标表备份
→ 仅执行所需增量迁移
→ 云库查询核对
→ 部署依赖新结构的后端
→ 验证线上 API
→ 上传/发布前端
→ 真机回归
```

禁止整库覆盖、禁止重复执行非幂等 SQL、禁止把本地测试用户和临时数据无选择地导入云库。

### 5.3 后端部署

- 上传包根目录必须包含 `Dockerfile`、`pom.xml`、`.dockerignore`、`src/`。
- 云托管按 Dockerfile 构建；查看构建日志、实例健康和流量切换结果。
- 新版本先小流量或人工验证，再接管全部流量；保留上一个稳定版本用于回退。
- 线上至少验证：健康接口、登录/手机号授权、学校列表与详情、收藏、留资、管理接口、图片与政策附件。

### 5.4 前端发布

- 微信开发者工具中核对正式 AppID、正式 API、隐私声明、版本号和构建结果。
- 先编译、真机预览，再上传体验版；审核通过不等于已经发布，需在公众平台执行发布。
- 发布后清缓存进行真机回归，特别关注登录门禁、详情来源、收藏、最近浏览、评价、祝福墙和留资。

完整步骤见《小程序完整上线发布操作手册》。

## 6. 业务模块与关键设计

主要模块包括：首页内容、国际学校、体制内小学/初中/高中/幼儿园、学校详情、查分与志愿、学校比对、排行榜、政策文章、开放日、收藏、最近浏览、五级评价、祝福墙、留资、反馈、用户管理和管理统计。

### 6.1 学校身份规则

多张学校表可能出现相同数字 ID，任何跨模块功能都必须使用复合身份：

```text
schoolSource + schoolId
```

已使用的来源包括 `international`、`score`、`general`、`junior`、`primary`、`kindergarten`。收藏、浏览、评价、祝福、反馈、最近浏览、比对和详情跳转都必须保留来源；只传 `schoolId` 会串校。

### 6.2 用户身份规则

- 微信 OpenID 是技术登录身份。
- 业务把已授权手机号视为客户归一依据；同手机号可能对应多个历史 OpenID。
- 服务端已有“同手机号选择最早主用户”的实现和一次云端历史归并，但相关代码是否已经上线必须验证。
- 管理端客户列表应只显示已授权手机号的用户并按手机号去重；未授权记录可用于访问漏斗，不应当成有效客户。
- 管理看板最终口径是“新增用户”，按最早 `create_time` 统计，不是日活/周活。

### 6.3 用户行为

- 进入学校详情开始计时，离开时上报；不足 3 秒视为误触。
- 同校多次浏览累计次数和时长；兴趣学校按累计时长优先、次数次之。
- 兴趣学校来自真实浏览，目标学校只能来自用户明确填写的留资，不可混用。

- HAR 和抓包数据只用于经授权的数据迁移与排障；不得保留无关 Cookie、Token、OpenID 或用户隐私。
- 来源公开不代表可无限抓取，继续采集需遵守服务条款、频率限制、著作权和个人信息保护要求。

## 13. 正式交接验收标准

只有同时满足以下条件，才算项目真正交接完成：

1. 代码、数据库、对象存储、微信平台、域名和服务器均由公司账号控制，不依赖离岗人员私人账号。
2. 新接手人能从干净环境独立启动前后端、执行迁移、制作上传包和完成真机测试。
3. 线上版本、Git 标签、数据库版本和发布记录能够一一对应。
4. 所有明文或历史暴露凭据已轮换，旧凭据失效。
5. 未上线功能的状态、负责人、优先级和验收标准已在任务系统登记。
6. 含个人信息、用户数据、HAR、数据库备份和私钥的资料已进入受控存储并设置最小权限。

---

维护说明：后续每次部署都应在总表追加“代码版本、数据库迁移、云托管版本、小程序版本、验证结果、回退点”，不要继续靠聊天记录推断生产状态。
