## 3. 必须轮换的高风险项

以下项目曾可能出现在历史源码、配置、文档、脚本或截图中，应按“已经暴露”处理：

- [ ] 云数据库业务账号密码
- [ ] 本地数据库共享密码
- [ ] OSS AccessKey/Secret
- [ ] 微信 AppSecret、会话相关密钥
- [ ] JWT 签名密钥
- [ ] 管理后台密钥
- [ ] 服务器 SSH 密码/私钥
- [ ] Git Personal Access Token/部署密钥
- [ ] SSL 私钥（如曾通过非受控渠道传递）

轮换顺序建议：先创建新凭据并灰度验证，再更新云环境变量和服务，确认业务正常后吊销旧凭据。不要先删旧凭据导致线上中断。

## 4. 历史敏感资料处置

- [ ] 已定位并限制访问历史 `HANDOVER.md`
- [ ] 已检查 `application.yml`、`application-cloud.yml` 和启动脚本
- [ ] 已检查聊天截图、云托管环境变量截图和部署截图
- [ ] 已检查 HAR、数据库导出、日志和 JVM 崩溃文件
- [ ] 已检查前端源码中不存在 AppSecret、数据库密码或管理密钥
- [ ] 已清除发布 ZIP 中的 `.git`、备份、日志、SQL dump 和本地配置
- [ ] 已确认离岗人员设备/个人网盘上的公司资料完成公司归档后按制度清理

## 5. 移交验收

- [ ] 接收人可在不联系原维护人员的情况下登录所有平台

- [ ] 已建立到期提醒：域名、SSL、云资源、数据库、OSS 和小程序认证
- [ ] 已完成一次数据库恢复演练和后端回退演练
