# 智能升学顾问前端交接（2026-09-11）

## 定位

这是免费、内嵌、规则驱动的升学客服，不调用大模型，不产生模型费用。后端负责问题顺序、答案识别、筛选规则和推荐结果；前端负责聊天气泡、快捷选项、学校卡片及留资表单。

## 1. 打开聊天页

```http
GET /api/advisor/welcome
```

公开接口，无需登录。返回：

```json
{
  "code": 200,
  "data": {
    "step": "stage",
    "reply": "你好，我是联朋智能升学顾问……",
    "context": {},
    "choices": [{"label":"小学","value":"小学"}],
    "schools": [],
    "canContact": false,
    "engine": "rule-based",
    "modelCost": 0
  }
}
```

## 2. 发送一轮消息

```http
POST /api/advisor/reply
Content-Type: application/json

{
  "message": "小学",
  "context": {}
}
```

每一轮必须把上轮响应的 `data.context` 原样传回。服务端会依次收集：学段、体制内外、行政区、学费预算和寄宿需求。用户既可以点击 `choices`，也可以输入短句；单轮文字最多按200字处理。

当 `step=result` 时，`schools` 最多返回6所，每所包含：`schoolId`、`schoolSource`、`name`、`district`、`logoUrl`、`schoolType`、`tuitionMin`、`tuitionMax`、`boardingInfo`。学校卡片跳转必须携带 `schoolSource + schoolId`，不能只传数字 ID。

当 `step=lead` 或 `canContact=true` 时显示“联系升学老师”。用户填写姓名、孩子年级、手机号、意向学校和问题后，继续调用现有登录接口：

```http
POST /api/lead/submit
Authorization: Bearer <token>
```

## 3. 前端页面要求

- 首页右上角放聊天图标，名称建议“升学顾问”。
- 助手回答显示 `reply`；快捷按钮完全由 `choices` 渲染，不在前端写死流程。
- `schools` 渲染成可点击学校卡片；无结果时保留“重新选择”和“联系升学老师”。
- 会话可保存在页面状态或本地缓存；重新开始时传 `message=重新选择`，并以服务端返回的新 `context` 为准。
- 明示“推荐用于初步筛选，请以学校最新招生政策为准”，不要宣称真人或通用 AI。
- 网络错误时保留当前 `context`，允许用户重试，不能自行跳到下一题。

## 4. 验收

- 小学/初中/高中与体制内/体制外组合都能走完流程。
- 区域不限、预算不限、寄宿不限均可返回结果。
- 体制内高中能合并两个高中数据源，重名学校不重复。
- 同数字 ID、不同来源的学校卡片均能正确进入各自详情。
- 输入“联系老师”进入留资引导；未登录时由现有登录流程接管。
- 接口响应始终为 `engine=rule-based`、`modelCost=0`。
