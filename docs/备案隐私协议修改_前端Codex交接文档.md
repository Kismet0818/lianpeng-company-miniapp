# 备案隐私协议修改——前端 Codex 交接文档

## 一、任务目标

为“联朋上海择校”微信小程序完成公安交互式备案材料中的“隐私协议修改”要求：

1. 在当前实际使用的新前端中找到隐私政策页面。
2. 修改前先保存一张 JPG 截图。
3. 在隐私政策中完善“未成年人保护”条款。
4. 编译并验证修改后的页面。
5. 保存一张修改后的 JPG 截图。
6. 将代码改动、截图路径和验证结果回报给用户。

本任务选择公安填写说明中的“未成年人保护”方案，不使用“生成式人工智能/深度合成”方案，因为本小程序是升学信息服务，未成年人保护与实际业务更匹配。

## 二、重要环境说明

- 新前端在前端同事的电脑上，以该电脑实际项目为唯一修改对象。
- 后端电脑 `C:\Users\Admin\WeChatProjects\lianpengshengxue` 中的是旧前端，不得将它覆盖或合并到新前端。
- 新前端工作区可能已有未提交修改。开始前先检查实际文件和版本状态，保留所有无关改动，禁止执行 `git reset --hard`、整目录覆盖等操作。
- 不修改后端接口、数据库、域名、AppID、登录流程或其他业务功能。

## 三、执行步骤

### 1. 定位实际隐私政策

在新前端项目中搜索以下关键词：

```text
隐私政策
隐私协议
未成年人保护
个人信息保护
privacy
agreement
```

确认用户在小程序中能进入该页面，并记录相关源文件路径。优先修改小程序内用户实际可见的隐私政策页面，不要只修改无入口的废弃文件。

如果隐私政策由微信公众平台的“小程序用户隐私保护指引”管理，而不是由代码渲染，应先向用户说明实际情况，再在对应管理入口修改；不要在代码中伪造一个没有用户入口的页面。

### 2. 保存修改前截图

在改代码之前，用微信开发者工具打开新前端当前的隐私政策页面，定位到现有“未成年人保护”条款。

截图要求：

- 能看到页面属于“联朋上海择校”的隐私政策。
- 能完整看清修改前的未成年人条款。
- 不要包含开发者工具控制台报错、其他用户隐私信息或无关窗口。
- 图片必须为 JPG 格式。

文件名：

```text
上海联朋公共关系策划有限公司小程序隐私协议修改前.jpg
```

截图必须在修改代码前保存。如果已经修改，先从版本历史中确认原文并恢复到原文状态截图，截完后再重新应用修改；不要凭空制作与实际页面不一致的“修改前”图片。

### 3. 修改未成年人保护条款

在现有隐私政策的“未成年人保护”章节中完善文案。若已有同类文字，应整合和替换，避免重复堆叠。建议最终正文如下：

```text
若您是未满18周岁的未成年人，您应在监护人的监护和指导下，并在获得监护人同意后，认真阅读并同意本隐私政策，方可使用“联朋上海择校”小程序及相关服务。未经监护人同意，未成年人不得自行向本平台提供个人信息。

若未成年人未取得监护人同意，监护人可通过本平台“关于我们”页面公布的联系方式通知上海联朋公共关系策划有限公司处理相关账号及个人信息。本平台有权依法对相关账号的功能和使用进行限制，包括但不限于浏览、发布信息和互动交流等功能。我们将依照法律法规要求，对未成年人个人信息采取严格的保护措施。
```

修改时注意：

- 公司全称必须是：`上海联朋公共关系策划有限公司`。
- 小程序名称使用备案对象显示的：`联朋上海择校`。
- 不要保留模板中的 `XX公司`、`XX软件`、`XX平台`。
- 不要添加本小程序不存在的聊天、直播、生成式人工智能等功能描述。
- 保持原页面样式、滚动和排版正常；只做本任务所需的最小改动。

### 4. 编译与页面验证

完成修改后执行新前端项目原有的编译/预览流程，并验证：

1. 项目能够正常编译，没有新增报错。
2. 从用户可见入口可以进入隐私政策。
3. “未成年人保护”标题和修改后的正文完整显示。
4. 文字没有被截断、重叠、溢出或被底部导航遮挡。
5. 公司名称、小程序名称和标点正确。
6. 其他隐私政策章节未被误删或改乱。

如果必须使用真机或体验版才能得到与线上一致的页面，应在不发布正式版本的前提下上传体验版验证；未经用户明确授权，不要提交正式审核或正式发布。

### 5. 保存修改后截图

在同一设备尺寸、同一页面和尽量相同的滚动位置截取修改后的条款，使公安审核人员能清楚对比前后差异。

文件名：

```text
上海联朋公共关系策划有限公司小程序隐私协议修改后.jpg
```

截图要求与修改前一致，且必须清楚显示新增的监护人同意、账号限制及未成年人个人信息保护内容。

### 6. 交付截图

将两张 JPG 放入用户指定的备案材料目录。若前端电脑无法直接访问后端电脑的 `C:\claude\上交的东西`，先放在新前端项目内单独的交付目录，再把准确路径告诉用户，由用户复制到备案材料目录。

不要把截图加入小程序构建包，不要提交包含真实用户数据的截图。
