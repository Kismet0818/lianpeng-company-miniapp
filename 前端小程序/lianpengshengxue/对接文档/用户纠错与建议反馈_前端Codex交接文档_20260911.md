# 用户纠错与建议反馈：前端 Codex 交接文档

> 更新时间：2026-09-11  
> 当前边界：后端代码与本地数据库已经完成；未修改任何前端代码；云数据库尚未建表，云托管尚未部署本功能。

## 1. 功能目标

参考同类小程序的“用户反馈”页面，为联朋升学增加以下入口：

- 纠错：学校资料、分数、政策文章等内容有误；
- 提供内容：用户希望补充资料或线索；
- 产品建议：页面、交互或功能建议；
- 用户查看自己提交过的反馈及平台处理结果。

后端不会信任前端传入的用户 ID 或 OpenID。用户身份统一从登录 JWT 中取得。

## 2. 前端页面建议

建议在“我的/用户信息”页面加入两个入口：

1. `纠错与建议`：进入反馈提交页；
2. `反馈与处理结果`：进入我的反馈列表页。

提交页字段：

- 本次反馈类型：纠错、提供内容、产品建议，三选一；
- 留言：必填，去除首尾空格后至少 5 个字，最多 2000 字；
- 相关截图：选填，最多 4 张；
- 联系方式：选填，最多 100 字；
- 当前页面路径：前端自动带入，最多 500 字；
- 如果从学校详情页进入，可额外自动带入 `schoolSource` 和 `schoolId`。

## 3. 枚举值

### 3.1 反馈类型 category

| 前端文案 | 请求值 |
|---|---|
| 纠错 | `correction` |
| 提供内容 | `content` |
| 产品建议 | `product` |

### 3.2 处理状态 status

| 状态值 | 前端文案 |
|---:|---|
| 0 | 待处理 |
| 1 | 处理中 |
| 2 | 已办结 |
| 3 | 已关闭 |

### 3.3 学校来源 schoolSource

可选值：`international`、`score`、`junior`、`general`、`primary`。

`schoolSource` 与 `schoolId` 必须同时传或同时不传。

## 4. 截图上传

截图不要转 Base64 放进反馈接口。沿用项目现有 OSS 直传流程：

1. 请求 `GET /api/oss/policy?dir=feedback` 获取直传参数；
2. 使用 `wx.uploadFile` 上传到返回的 OSS `host`；
3. 得到 HTTPS 图片地址；
4. 最多收集 4 个地址，作为 `screenshotUrls` 数组提交。

后端已将 `feedback` 加入 OSS policy 目录白名单。每个截图地址必须以 `https://` 开头。

## 5. 用户提交反馈

### 接口

`POST /api/feedback`

需要登录 JWT，使用项目统一 `request` 工具，不要手写用户 ID。

### 请求示例

```json
{
  "category": "correction",
  "message": "这所学校的地址已经发生变化，请核对。",
  "screenshotUrls": [
    "https://example-bucket.oss-cn-shanghai.aliyuncs.com/feedback/example.png"
  ],
  "contact": "微信：example",
  "pagePath": "/pages/school-detail/school-detail?id=123&schoolSource=junior",
  "schoolSource": "junior",
  "schoolId": 123
}
```

非学校页面提交时，省略 `schoolSource` 和 `schoolId`。

### 主要校验

- `category` 必须是三个枚举值之一；
- 留言至少 5 字、最多 2000 字；
- 截图最多 4 张；
- 联系方式最多 100 字；
- JWT 用户必须存在且具有 OpenID；
- 新反馈状态固定为 0，前端不能指定状态和处理结果。

成功后 `data` 返回完整反馈对象。

## 6. 用户查看反馈与处理结果

### 接口

`GET /api/feedback/mine?page=1&size=20`

需要登录 JWT，只返回当前用户自己的记录。`size` 最大 50。

### data 分页结构

```json
{
  "records": [
    {
      "id": 1,
      "category": "correction",
      "message": "这所学校的地址已经发生变化，请核对。",
      "screenshotUrls": [],
      "contact": null,
      "pagePath": "/pages/example/example",
      "schoolSource": null,
      "schoolId": null,
      "status": 2,
      "handlingResult": "已经核对并修正，感谢反馈。",
      "handledAt": "2026-09-11T14:00:00",
      "createTime": "2026-09-11T13:00:00",
      "updateTime": "2026-09-11T14:00:00"
    }
  ],
  "total": 1,
  "current": 1,
  "size": 20
}
```

列表建议显示：类型、留言摘要、状态、提交时间。点进详情后显示全部留言、截图、联系方式和 `handlingResult`。处理结果为空时显示“平台暂未回复”。

## 7. 管理端接口（前端小程序不要调用）

以下接口由管理后台使用，必须携带 `X-Admin-Key`：

- `GET /api/admin/feedback?page=1&size=20&status=0&category=correction&keyword=学校`
- `PUT /api/admin/feedback/{id}`

处理请求：

```json
{
  "status": 2,
  "handlingResult": "已经核对并修正，感谢反馈。"
}
```

当状态改为 2（已办结）或 3（已关闭）时，处理结果必填。

## 8. 前端错误处理

后端继续使用项目统一 `Result`：成功 `code=200`，业务校验错误返回具体 `message`。前端应优先展示后端 `message`，不要统一替换成“服务器内部错误”。

需要特别处理：

- 登录失效：走现有重新登录流程；
- 截图上传中：禁用提交按钮，全部上传成功后再提交；
- 部分截图上传失败：保留已成功图片，提示用户重试或删除失败项；
- 防止连续点击：提交期间按钮 loading，成功后不要重复 POST。
