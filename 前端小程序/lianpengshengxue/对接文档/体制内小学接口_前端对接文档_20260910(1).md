# 体制内小学接口前端对接文档

## 1. 结论与部署要求

后端新增独立小学资源接口，不与 `school`、`junior_high_school`、`general_high_school` 等表共用 ID 空间。接口公开，无需 JWT；部署后必须重启 Spring Boot 服务才能加载新 Controller。

- 列表：`GET /api/primary-schools`
- 详情：`GET /api/primary-schools/{id}`
- 固定来源：`schoolSource = "primary"`
- 固定学段：`schoolLevel = "小学"`
- `id` 仅代表 `primary_school.id`，前端缓存、收藏、埋点或跳转时必须同时保留 `schoolSource`，不得跨表复用。

## 2. 列表查询参数

| 参数 | 必填 | 默认值/上限 | 规则 |
|---|---|---|---|
| `page` | 否 | 默认 1 | 小于 1 时按 1 处理 |
| `size` | 否 | 默认 20，最大 500 | 小于 1 时按 1，超过 500 时按现有限流规则处理 |
| `district` | 否 | 无 | 区名精确匹配，如 `浦东新区`；UTF-8 URL 编码 |
| `keyword` | 否 | 无 | 对全名、简称模糊搜索 |
| `name` | 否 | 无 | 兼容参数；`keyword` 有值时优先使用 `keyword` |
| `schoolType` | 否 | 无 | 精确匹配，当前数据为 `公办`/`民办` |
| `tier` | 否 | 无 | 精确匹配：`一梯队`/`二梯队`；无梯队记录的值为 `null` |

默认稳定排序为 `district ASC, name ASC, id ASC`。

## 5. 鉴权、错误与前端处理

- 列表和详情均已加入 JWT 公开白名单，但仍受公共查询限流保护。
- 空列表：业务码 200，`records=[]`、`total=0`。
- 无图片/简介：对应字段返回 `null`，前端使用占位图或隐藏区块。
- 无效 ID：HTTP 200，业务响应 `{"code":400,"msg":"小学不存在","data":null}`；前端按业务码显示不存在页。
- 401/403：通常代表部署版本未加载白名单或网关另有鉴权，提示重新登录并联系后端。
- 429：遵循 `Retry-After`，不要立即循环重试。
- 500：显示通用错误并记录请求参数、request ID；不要把空对象当成功。

## 8. 梯队数据说明与限制

来源为 `C:\claude\G类：上海16区一二线公办小学名单.xls` 第一张主名单工作表，共识别 96 个学校名单行。采用“区 + 标准化学校全名/简称”匹配，校区拆行的学校按同一梯队更新；只写入可靠匹配结果：一梯队 31 条、二梯队 37 条、未列入或无法可靠对应的 99 条为 `null`。

Excel 中有 31 所学校在当前数据库里没有可靠同名记录（典型包括松江实验小学、民乐小学、三新学校小学部等），未用相似名称强行匹配。后续如补录这些学校，可重新运行 `tools/audit_primary_school_tiers.py` 预演并人工审核后写入。

## 9. 前端改动清单

- 学校库学段选择增加“小学”，请求 `/api/primary-schools`。
- 小学卡片和详情沿用现有字段；展示梯队时读取 `tier`，值为 null 时不显示梯队标签。
- 跳转参数、缓存键、收藏/埋点对象同时保存 `schoolSource=primary` 和小学 `id`。
- 评价、祝福墙、浏览行为统计和后台用户行为解析现已支持 `schoolSource=primary`。
- 小学对比优先调用 `POST /api/primary-schools/compare`，请求体 `{"schoolIds":[100026,100061]}`；旧的 `POST /api/schools/compare` 也已兼容显式 `schoolSource=primary`，并能对 100000 以上的小学新 ID 自动识别。
