# 学校比对功能后端 Codex 工作文档

> 文档版本：v1.0  
> 更新时间：2026-09-14  
> 项目：联朋升学微信小程序  
> 执行对象：后端 Codex  
> 目标：为“学校比对”页面提供按学段直接搜索学校、加入对比列表并返回详细对比数据的后端能力。

## 一、业务目标

新增独立的学校比对入口：

1. 用户选择学段：`初中` 或 `高中`；
2. 输入学校名称或关键词并搜索；
3. 搜索结果展示学校摘要，用户点击“加入对比”；
4. 对比列表保存学校的稳定唯一标识；
5. 点击“开始对比”后，返回对比列表中学校的完整对比数据；
6. 对比字段、展示语义应与现有学校库中的学校对比功能一致。

本需求与学校库对比的区别仅在于“学校如何加入列表”：学校库从列表中直接选择；本功能从搜索接口返回结果中选择。两者必须兼容同一套对比数据模型。

## 二、执行边界

后端 Codex 必须完成：

- 数据表和现有数据源的确认；
- 搜索接口；
- 批量对比详情接口或兼容现有对比接口；
- 唯一标识、学段隔离、排序和错误处理；
- 接口测试及联调样例；
- 本文档中“后端完成后必须生成”的前端对接文档。

后端不得修改微信小程序页面，不得要求前端直接连接数据库，不得让前端根据学校名称自行拼接学校详情。

## 三、现有项目约定（必须兼容）

统一响应格式：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {}
}
```

当前前端统一调用 `utils/request.js`，业务成功必须返回 HTTP 2xx 且业务 `code=200`。

现有学校来源标识：

| 数据来源 | `schoolSource` | 对比键格式 |
|---|---|---|
| 体制外学校库 | `international` | `international:{id}` |
| 分数查询高中/市重点/区重点 | `score` | `domestic:{kind}:{id}` |
| 初中 | `junior` | `domestic:junior:{id}` |
| 一般高中 | `general` | `domestic:general:{id}` |

本次“初中/高中”默认指体制内学校。高中必须覆盖现有高中数据源：市重点、区重点、一般高中；如数据库中存在其他高中类型，也必须在文档中明确归类。

## 四、接口一：学校搜索

### 4.1 请求

```text
GET /api/school-compare/search
```

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `level` | string | 是 | `junior` 初中，`high` 高中 |
| `keyword` | string | 是 | 学校名称关键词，去除首尾空格后长度 1-50 |
| `page` | integer | 否 | 默认 1 |
| `size` | integer | 否 | 默认 20，最大 50 |

搜索应支持学校全称和名称包含匹配；数据库查询必须使用参数化查询。默认按“名称完全匹配、名称前缀匹配、名称包含匹配、名称拼音/别名（若已有字段）”优先级排序，再按学校名称和 ID 稳定排序。

### 4.2 成功响应

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "records": [
      {
        "id": 123,
        "compareKey": "domestic:junior:123",
        "schoolSource": "junior",
        "kind": "junior",
        "level": "初中",
        "name": "示例初级中学",
        "shortName": "示例初中",
        "district": "浦东新区",
        "schoolType": "公办",
        "boardingInfo": "无寄宿",
        "logoUrl": ""
      }
    ],
    "page": 1,
    "size": 20,
    "total": 1,
    "hasMore": false
  }
}
```

字段要求：`id` 必须是对应原始学校表主键；`compareKey` 必须由后端生成；不得用数组下标或名称作为唯一 ID。无图片时返回空字符串或 `null`，不要返回失效的临时地址。

### 4.3 空结果和参数错误

- 合法搜索但无结果：仍返回 `code=200`，`records=[]`，`total=0`；
- 缺少 `level`、`keyword` 或 level 非法：HTTP 400，返回明确错误信息；
- 关键词长度超限：HTTP 400；
- 不得把“无结果”作为 500 错误。

## 五、接口二：批量获取对比详情

优先扩展现有接口，使学校库和新页面共用：

```text
POST /api/school-compare/details
```

请求体：

```json
{
  "schools": [
    { "schoolSource": "junior", "id": 123 },
    { "schoolSource": "general", "id": 456 }
  ]
}
```

规则：

- 学校数量最少 1，最多 6；
- 同一请求只能包含同一大类学段：全部 `junior`，或全部高中来源；
- 初中和高中混合时返回 400；
- 重复学校去重；
- 返回顺序必须与请求首次出现顺序一致；
- 找不到任一学校时返回 404，并指出缺失的 `schoolSource/id`，不得静默替换成同 ID 的其他来源学校。

成功响应：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "schoolSystem": "domestic",
    "level": "junior",
    "schools": [
      {
        "id": 123,
        "compareKey": "domestic:junior:123",
        "schoolSource": "junior",
        "kind": "junior",
        "name": "示例初级中学",
        "district": "浦东新区",
        "level": "初中",
        "schoolType": "公办",
        "nature": "公办",
        "tuitionMin": null,
        "tuitionMax": null,
        "boardingInfo": "无寄宿",
        "logoUrl": ""
      }
    ]
  }
}
```

`schools` 中应返回学校库现有对比所需的完整字段。至少保证前端当前对比表使用的字段可用：`name`、`district`、`level`、`schoolType/nature`、`tuitionMin`、`tuitionMax`、`boardingInfo`、`logoUrl`。如果某字段不适用，返回 `null`，不要伪造数据。

## 六、与现有接口的兼容要求

现有接口：

```text
POST /api/schools/compare
```

该接口服务体制外学校库，不能被本需求改成接收体制内学校 ID。若后端决定统一为一个接口，必须同时兼容现有请求和响应，且必须通过 `schoolSource` 区分数据源。

不能将以下 ID 混用：

- `school.id`；
- `score_query_tool_school.id`；
- `junior_high_school.id`；
- `general_high_school.id`。

同数字 ID 在不同表中必须被视为不同学校，查询必须带来源。

## 七、对比业务规则

- 对比列表最多 6 所；超过上限返回 400，错误信息建议为“最多选择6所学校进行对比”；
- 同一学校重复加入时返回或处理为幂等，不产生重复列；
- 初中只能与初中对比，高中只能与高中对比；
- 高中内部允许市重点、区重点、一般高中混合，前提是字段口径一致；
- 后端不保存用户的临时对比列表，列表由前端本地维护；
- 后端不得依赖登录态，接口可匿名调用；
- 所有详情接口必须避免 N+1 查询，批量接口应一次性完成或使用明确的批量查询。

## 八、验收与测试

后端完成前必须提供自动化测试或可重复的接口测试，至少覆盖：

1. 初中关键词命中、无结果、特殊字符和超长关键词；
2. 高中关键词命中市重点、区重点、一般高中；
3. 同名学校但不同来源时不会串数据；
4. 初中和高中混合请求被拒绝；
5. 1、6、7 所对比边界；
6. 重复学校去重且顺序稳定；
7. 缺少字段时按 `null` 返回，不导致 500；
8. 返回字段与现有学校库对比页面实际使用字段一致。

请至少提供以下 curl 示例及实际响应：

```bash
curl "http://localhost:8080/api/school-compare/search?level=junior&keyword=实验"
curl "http://localhost:8080/api/school-compare/search?level=high&keyword=中学"
curl -X POST "http://localhost:8080/api/school-compare/details" -H "Content-Type: application/json" -d "{\"schools\":[{\"schoolSource\":\"junior\",\"id\":123},{\"schoolSource\":\"junior\",\"id\":124}]}"
```

## 十、完成判定

满足以下条件才可标记完成：

- 搜索接口可按初中/高中稳定返回正确来源和唯一标识；
- 批量详情接口返回现有对比页需要的完整数据；
- ID 不串表、不串学段；
- 6 所上限、同学段限制和错误响应已实现；
- 自动化测试或接口测试通过；
- `学校比对_前端对接文档.md` 已生成并与实际实现一致。
