# 中考查分工具祝福墙后端对接文档

## 一、需求说明

在中考查分工具页面展示 `blessing` 表中最新的 6 条有效祝福。

该模块展示的是 `blessing` 表的全量数据，不按学校筛选，也不限定 `school_source`。前端只负责调用接口和展示，不能直接连接或读取数据库。

## 二、接口要求

请提供以下接口：

```http
GET /api/blessing/list?page=1&size=6
```

接口不得要求 `schoolSource`、`schoolId` 等学校筛选参数。该接口用于祝福墙的全局数据展示。

如果现有接口同时用于学校详情页，请保持原有带学校参数的逻辑不变：

```http
GET /api/blessing/list?page=1&size=20&schoolSource=score&schoolId=52
```

无 `schoolSource` 和 `schoolId` 时返回全局祝福；有这两个参数时按学校筛选。

## 三、数据库查询要求

数据来源：`blessing` 表。

建议查询逻辑：

```sql
SELECT
  openid,
  nickname,
  avatar,
  school_source,
  school_id,
  school_name,
  content,
  created_at
FROM blessing
WHERE school_name IS NOT NULL
  AND school_name <> ''
ORDER BY created_at DESC, id DESC
LIMIT 6 OFFSET 0;
```

注意：

1. 不要在无学校参数时自动追加 `school_source = 'score'`。
2. 祝福墙需要全量来源数据，包括 `score`、`junior`、`general` 等来源。
3. `school_name` 直接使用 `blessing.school_name`，不需要联表查询。
4. `school_name` 为空的记录不应返回到祝福墙，否则前端无法展示学校名称。
5. 排序必须按最新创建时间倒序，不能按学校或昵称排序。
6. 如果项目实际时间字段不是 `created_at`，请使用实际创建时间字段，并在报告中注明。

## 四、响应格式

请保持项目统一响应格式：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "records": [
      {
        "id": 1,
        "openid": "openid-example",
        "nickname": "何意味",
        "avatar": "https://example.com/avatar.jpg",
        "school_source": "score",
        "school_id": 146,
        "school_name": "上海立信会计金融学院附属中学",
        "content": "祝孩子中考顺利，沉着发挥！",
        "created_at": "2026-09-09T10:30:00+08:00"
      }
    ],
    "current": 1,
    "pages": 1,
    "total": 6,
    "size": 6
  }
}
```

前端依赖的字段只有：

- `nickname`：展示祝福者昵称
- `school_name`：展示学校名称
- `content`：前端只取第一个空格前的内容，例如 `祝孩子`

字段名称请保持为下划线格式；如果后端统一返回驼峰格式，请提前在报告中说明，并同步提供明确的字段映射。

## 五、异常响应

请求成功但没有有效数据时，也应返回 HTTP 200：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "records": [],
    "current": 1,
    "pages": 0,
    "total": 0,
    "size": 6
  }
}
```

不要因为没有学校筛选参数而返回“学校参数不正确”。

## 六、验收数据

请使用当前 `blessing` 表中的真实数据测试，并至少确认：

1. 无任何查询参数时接口可以正常返回。
2. 返回结果包含多种 `school_source` 的数据，不被限定为 `score`。
3. 返回记录的 `school_name` 与数据库原值一致。
4. 返回结果按创建时间倒序排列。
5. 数据库中有有效记录时，`records` 不为空。
6. 数据库中 `school_name` 为空的记录不会进入祝福墙结果。
7. 访问接口不会出现“学校参数不正确”。
8. 带 `schoolSource` 和 `schoolId` 的学校详情页查询仍然正常，不受本次全局查询逻辑影响。
