# 一般高中接口鉴权导致学校名录全部为空

## 一、问题现象

进入小程序：

```text
查分工具 → 中考招生信息查询 → 选择地区 → 学校名录
```

“市重点、区重点、一般高中”均显示：

```text
学校名录数据待接入
```

页面未持续加载，不是前端卡顿。

## 二、接口检测结果

以下接口能够正常返回数据：

```http
GET /api/score-query/volunteer?year=2025-2026
GET /api/score-query/region?year=2025-2026
GET /api/score-query/schools/district-key?district=崇明区
```

一般高中接口返回：

```http
GET /api/general-high-schools?page=1&size=500&district=崇明区
```

响应内容：

```json
{
  "code": 401,
  "msg": "未授权，请先登录",
  "data": null
}
```

HTTP 状态码为 `200`，业务状态码为 `401`。

## 三、影响范围

一般高中接口与市重点、区重点接口通过 `Promise.all` 并行加载。

一般高中接口返回业务错误后，整个 `Promise.all` 被拒绝，导致已经成功返回的市重点、区重点数据也无法写入页面，所以所有分类一起显示为空。

## 四、原因判断

`/api/general-high-schools` 当前受到 JWT 拦截器保护，但学校名录页面属于公开查分功能，不应依赖用户登录状态。

数据库连接正常，市重点和区重点接口也能正常返回数据。本次问题主要属于一般高中接口的访问权限配置问题。

## 五、需要后端处理

请将以下一般高中只读查询接口加入 JWT 公开白名单：

```text
GET /api/general-high-schools
GET /api/general-high-schools/{id}
```

建议放行路径：

```text
/api/general-high-schools
/api/general-high-schools/**
```

新增、修改、删除等管理接口仍应保留管理员鉴权，不要一并公开。

## 六、接口要求

列表接口：

```http
GET /api/general-high-schools?district=崇明区
```

详情接口：

```http
GET /api/general-high-schools/{id}
```

统一响应格式：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {}
}
```

字段建议保持与 `general_high_school` 表一致，并转换为前端使用的驼峰格式：

```text
id
name
shortName
backgroundImageUrl
district
tuitionMin
tuitionMax
boardingInfo
schoolType
address
description
```

列表需要按照 `district` 精确筛选，并使用 `general_high_school.id`，不能复用其他学校表的 ID。

## 七、前端配合处理

前端会同时增加独立容错：一般高中接口失败时仅清空“一般高中”，不再影响市重点和区重点。

请后端完成白名单配置和服务重启后通知前端重新联调。
