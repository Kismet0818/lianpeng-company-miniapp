## 前端电脑必须先做的检查

### 1. 确认导入的是完整项目根目录

微信开发者工具所选目录中必须直接看到：

```text
app.js
app.json
app.wxss
project.config.json
pages/
utils/
custom-tab-bar/
```

不要打开压缩包外层目录，也不要只打开 `pages` 或几个增量文件。确认项目类型是“小程序”，不是小游戏、插件或云开发目录。

### 2. 核对本地联调配置

`app.js` 应保持：

```javascript
useCloud: false
```

前端电脑若与后端电脑都使用 Wi-Fi，优先测试：

```javascript
localBaseUrl: 'http://192.168.3.18:8080'
```

若明确通过有线局域网访问，则可使用：

```javascript
localBaseUrl: 'http://192.168.3.5:8080'
```

先在前端电脑浏览器分别打开以下地址，以实际能返回 JSON 的地址为准：

```text
http://192.168.3.18:8080/api/home/overview
http://192.168.3.5:8080/api/home/overview
```

不要同时改 `useCloud:true`。云端当前仍是旧后端，不适合本次本地联调。

### 3. 清理开发者工具状态

在微信开发者工具中依次执行：

1. 详情 → 本地设置 → 勾选“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。
2. 清缓存 → 全部清除。
3. 重新编译。
4. 如果仍白屏，关闭项目并重新导入项目根目录。
5. 暂时把调试基础库切换到一个稳定版本重新编译，记录版本号。

### 4. 根据第一条红色错误分类处理

- `Page ... is not found`：检查 `app.json` 路径以及对应页面四个文件。
- `module ... is not defined` / `module not found`：检查 `require` 相对路径和源码包是否完整。
- `App is not registered` / `Page is not registered`：优先修复 `app.js` 或首屏脚本最前面的异常。
- WXML/WXSS 编译错误：按照编译器给出的文件和行号修复，先处理第一条。
- `request:fail`：核对 `localBaseUrl`、同一局域网、开发工具域名校验设置；这类错误本身不应让已有静态页面完全白屏。
- `setData`、`undefined`、组件生命周期异常：根据调用栈检查 `pages/home/home.js` 和自定义 tabBar。
- 没有红色错误但仍白屏：在 `app.js onLaunch`、`pages/home/home.js onLoad/onShow` 首行增加临时日志，确认生命周期是否执行；再检查 WXML 根节点是否生成、模拟器是否被调试面板遮挡。

### 5. 比对源码版本

前端电脑上的源码可能与后端电脑基准版本不同。请用目录比较或 Git 对比，至少核对：

```text

```

不要只凭文件名相同判断内容一致，也不要直接覆盖来源不明的前端改动。
